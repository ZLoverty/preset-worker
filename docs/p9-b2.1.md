# P9-B2.1 — Element-Wise Array Comparison

Update the existing Bambu Studio Preset–3MF consistency validator to support element-wise array comparison.

The objective is to compare stored configuration values, not to reconstruct runtime-effective values.

## Requirements

1. Treat each supported parameter as an ordered array when both inputs are arrays.
2. Expand every element into an individually addressable comparison entry, such as `nozzle_temperature[0]` and `nozzle_temperature[1]`.
3. Compare values at the same array index when the two arrays have equal lengths and verified compatible storage semantics.
4. Normalize numeric strings before comparison.
5. Preserve the original array, element index, raw value, normalized value, and source path.
6. Do not require filament-slot or nozzle-variant resolution for element-wise stored-value comparison.
7. Do not claim that equal array elements prove runtime-effective consistency.
8. Do not truncate arrays or silently broadcast single-element arrays.
9. When array lengths differ, report `AMBIGUOUS` or `NOT_COMPARABLE` unless a verified mapping establishes element correspondence.
10. Preserve all unmatched elements in the report.
11. Treat scalar-versus-array comparisons as `NOT_COMPARABLE` unless a documented parameter-specific rule permits conversion.
12. Keep the eight existing parameter IDs and their normalization rules unchanged.

## Reporting

The report must distinguish:

- Parameter-level summary.
- Element-level comparison results.
- Stored-value consistency.
- Runtime-effective resolution status, if available.

For example:

```json
{
  "parameter_id": "nozzle_temperature",
  "comparison_scope": "STORED_ARRAY",
  "status": "MISMATCH",
  "elements": [
    {
      "index": 0,
      "preset_value": "350",
      "project_value": "350",
      "status": "MATCH"
    },
    {
      "index": 1,
      "preset_value": "320",
      "project_value": "325",
      "status": "MISMATCH"
    }
  ]
}
```

Parameter-level status aggregation:

- All comparable elements MATCH → MATCH.
- Any comparable element MISMATCH → MISMATCH.
- Array lengths differ without verified mapping → AMBIGUOUS.
- Invalid or missing values → appropriate explicit status.

Do not mix element-level counts with parameter-level counts in the same summary.

## Tests

Add tests for:

- Equal-length matching arrays.
- Equal-length arrays with one mismatching element.
- Different-length arrays.
- Scalar versus array.
- Numeric strings versus numbers.
- Missing and invalid elements.
- H2D two-element arrays.
- All four cooling parameters.
- Deterministic JSON reporting.

Preserve the existing standalone CLI and do not modify Worker, Feishu, or Miaoda integration.

Update the comparison documentation and implementation report.
