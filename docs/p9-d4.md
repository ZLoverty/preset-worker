# P9-D4 — PrusaSlicer Consistency Adapter

## Background

The Preset Management System has completed the following P9 stages:

- **P9-B2:** BambuStudio consistency validation.
- **P9-D0:** Cross-slicer real-fixture investigation.
- **P9-D1:** Shared comparison core and slot-aware comparison.
- **P9-D2:** CrealityPrint and ElegooSlicer consistency adapters.
- **P9-D3:** OrcaSlicer and SnapmakerOrcaSlicer consistency adapters.

Five slicers now have independently callable consistency validators. PrusaSlicer is the remaining unsupported slicer.

Existing shared components include:

```text
src/preset_worker/three_mf/
├── safe_zip.py
├── bambu_parser.py
├── comparison_core.py
├── consistency.py
└── native_consistency.py
```

Verify the actual repository structure before implementation.

The existing shared comparison core provides:

- Canonical parameter comparison.
- Numeric normalization.
- Explicit filament-slot selection.
- Duplicate-identity handling.
- Stored-value comparison statuses.
- Source provenance.

The native consistency orchestration provides compatible report construction using:

`p9b2.consistency.v1`

P9-D4 must reuse these components wherever their contracts are applicable.

### P9-D0 PrusaSlicer findings

The real fixture pair is expected at:

```text
tests/fixtures/slicers/prusa_slicer/
├── prusa.3mf
├── pla_test.ini
└── manifest.json
```

The recorded fixture characteristics are:

- PrusaSlicer version: `2.9.6`.
- Printer: `COREONE_INDX4T`.
- Project settings member: `Metadata/Slic3r_PE.config`.
- Project configuration uses an INI-style format.
- The project contains four filament configuration entries.
- The native Preset does not expose a usable `filament_settings_id` in the same manner as the Bambu-style slicers.
- The Preset filename stem `pla_test` matches a unique project filament profile at slot 1.
- Identity evidence was classified as `UNIQUE_BY_FILENAME`.

Six candidate parameter mappings were identified:

| Canonical parameter | Native PrusaSlicer parameter |
|---|---|
| `nozzle_temperature` | `temperature` |
| `nozzle_temperature_initial_layer` | `first_layer_temperature` |
| `fan_min_speed` | `min_fan_speed` |
| `fan_max_speed` | `max_fan_speed` |
| `fan_cooling_layer_time` | `fan_below_layer_time` |
| `slow_down_layer_time` | `slowdown_below_layer_time` |

The mappings for `filament_flow_ratio` and `filament_max_volumetric_speed` remain unverified.

These are investigation findings, not permission to assume every mapping or identity relationship is universally valid.

## Objective

Implement an independently callable PrusaSlicer consistency validator that:

1. Parses native PrusaSlicer INI Presets.
2. Safely extracts PrusaSlicer project configuration from 3MF.
3. Establishes filament identity using explicit, documented evidence.
4. Selects the correct filament slot.
5. Maps verified native parameters into the eight canonical P9 parameters.
6. Reuses the shared comparison core.
7. Produces a compatible `p9b2.consistency.v1` report.
8. Preserves unresolved or ambiguous evidence without fabricating matches.
9. Passes real-fixture and negative tests.
10. Leaves production Preview routing unchanged.

Do not implement a second comparison engine.

## D4.2 — Safe PrusaSlicer 3MF Extraction

Implement a minimal PrusaSlicer-specific project extractor.

Suggested module:

`src/preset_worker/three_mf/prusa_parser.py`

Use the existing `SafeZipReader` for all archive access.

Read:

`Metadata/Slic3r_PE.config`

Parse the configuration according to the actual PrusaSlicer format found in the real fixture.

The parser must preserve:

- Original project parameter names.
- Original parameter values.
- Source member path.
- Source key or section.
- Filament profile identity evidence.
- Filament slot ordering.
- Array or list representation.
- Source provenance.

Do not assume this is identical to a standard Python `configparser` INI document.

Inspect the real syntax first, including repeated keys, comments, quoting, delimiters, escaping, and array conventions.

Reuse existing INI parsing utilities where compatible.

Do not create a second general-purpose INI parser unnecessarily.

### Safety requirements

Preserve the existing ZIP safety behavior:

- Reject unsafe archive paths.
- Enforce archive and member size limits.
- Handle missing members.
- Handle malformed project configuration.
- Handle unsupported encodings explicitly.
- Do not execute or evaluate project content.

Do not use unrestricted extraction
