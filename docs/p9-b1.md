# P9-B1 — Bambu Studio 3MF Parser and Effective Configuration Extraction

## 1. Objective

Implement a production-quality, read-only Bambu Studio 3MF parsing and parameter extraction module, based on the findings of P9-A.

The module must:

1. Safely parse Bambu Studio `.3mf` archives.
2. Extract project, model, plate, filament, printer, and process configuration metadata.
3. Identify filament slots and their relationships to objects, volumes, plates, and extruders.
4. Resolve configuration indices and effective parameter values only when supported by verified rules.
5. Preserve complete provenance for every extracted value.
6. Explicitly represent unresolved, ambiguous, and unsupported cases.
7. Provide a standalone diagnostic CLI for inspecting real 3MF files.
8. Establish a tested, reusable foundation for P9-B2 consistency comparison.

**P9-B1 must not compare extracted 3MF parameters against a submitted Filament Preset JSON.**

It must not modify the existing Worker lifecycle, Feishu schema, or Miaoda frontend.

## 2. Context and P9-A Findings

The existing system uses:

- Python Worker
- Feishu Bitable as the source of truth
- Submission, PresetVersion, and Preset tables
- BambuStudioProcessor for native JSON processing
- Artifact abstraction for binary source files
- UnifiedDiff for Preset version comparison

Relevant existing files include:

- `src/preset_worker/slicers/bambu_studio.py`
- `src/preset_worker/slicers/contracts.py`
- `src/preset_worker/services/projection.py`
- `src/preset_worker/diff.py`

P9-A identified the following Bambu Studio 3MF entries:

- `Metadata/project_settings.config` — JSON project configuration snapshot
- `Metadata/model_settings.config` — XML object/volume configuration
- `Metadata/slice_info.config` — XML slice metadata
- `Metadata/filament_sequence.json` — filament sequence metadata
- Optional embedded filament, machine, and process preset entries
- Optional plate-specific metadata

P9-A also established that:

- A parameter array is not necessarily indexed by filament slot.
- `filament_settings_id` array length may differ from parameter array lengths.
- Bambu Studio uses `get_filament_config_idx()` and related mapping logic.
- Configuration resolution may depend on filament map, extruder type, filament volume map, nozzle variant, and other context.
- Object-level `print_flow_ratio` must not be confused with filament-level `filament_flow_ratio`.
- `nil`, missing values, and inherited values cannot be treated as effective defaults.
- Pressure Advance values in a Bambu printer project do not necessarily represent effective printer behavior.

The existing P9-A reports are the starting point. Verify their findings against the repository, fixtures, and relevant Bambu Studio source code.

This is a suggested structure, not a mandatory one. Follow existing repository conventions.

Keep parsing separate from effective-value resolution.

Suggested public API:

```python

    artifact: Artifact,

resolve_bambu_project(
    snapshot: BambuProjectSnapshot,
    context: ResolutionContext | None = None,

```

The parser must not require Feishu records, network access, or Worker lifecycle state.

Use typed, serializable data models compatible with the project's existing Python conventions.

Avoid introducing unnecessary dependencies.

## 5. Safe ZIP Reader

Implement a reusable ZIP reader that operates on bytes or file-like input.

Before parsing archive contents, inspect ZIP metadata and enforce configurable limits.

Suggested initial defaults:

| Limit | Value |
|---|---|
| Maximum compressed archive size | 256 MiB |
| Maximum total uncompressed size | 1 GiB |
| Maximum entry count | 10,000 |
| Maximum single entry size | 256 MiB |
| Maximum compression ratio | 100:1 |

These are provisional limits. Evaluate them against real Bambu Studio 3MF fixtures and existing Worker upload limits.

Security requirements:

- Never call unrestricted `extractall()`.
- Reject absolute paths.
- Reject path traversal.
- Reject duplicate normalized archive paths.
- Reject unsupported compression methods.
- Reject malformed ZIP structures.
- Bound actual decompressed bytes, not only ZIP header-declared sizes.
- Enforce memory and parser limits.
- Handle malformed JSON and XML safely.
- Disable external XML entities and external resource resolution.
- Do not allow filesystem or network access through XML parsing.
- Provide structured errors without exposing sensitive local paths.

Large geometry and thumbnail entries should not be loaded into memory unless necessary.

Prefer reading only relevant configuration entries.

Test ZIP bombs, malformed archives, duplicate entries, traversal attempts, and resource limits.

- Object-to-extruder assignments.
- Volume-to-extruder assignments.
- Object-level overrides.
- Volume-level overrides.
- Plater metadata.
- Filament map information.

### 6.3 Plate Metadata

Inspect available plate-specific entries.

Extract:

- Plate identifiers.
- Plate type.
- Filament mapping.
- Relevant extruder/nozzle context.
- Other configuration metadata needed for later parameter resolution.

Do not infer plate count from thumbnail count alone.

### 6.4 Optional Embedded Presets

Detect embedded filament, machine, and process preset entries.

Record:

- Archive path.
- Preset type.
- Preset identifier.
- Parsed metadata where supported.

Do not assume embedded presets exist.

### 6.5 Other Entries

Inspect slice information and filament sequence metadata.

Extract useful context, but do not treat filament sequence data as the authoritative source of filament preset parameters.

## 8. Configuration Index Resolution

**This is the highest-priority correctness requirement.**

P9-A found a real H2D project with:

```json
{
  "filament_settings_id": ["PPS100CF10 H2D"],
  "filament_flow_ratio": ["1", "0.96"],
  "nozzle_temperature": ["350", "320"],
  "retraction_length": [
    "0.8",
    "0.8",
    "0.8",
    "0.8",
    "0.8"
  ]
}
```

This demonstrates that configuration arrays have different cardinalities.

Do not implement:

```python
effective_value = values[filament_slot - 1]
```

as a universal rule.

Investigate the relevant Bambu Studio source code, particularly:

- `get_filament_config_idx()`
- Filament-to-extruder mapping
- Filament volume mapping
- Extruder type handling
- Filament variant handling
- Nozzle configuration
- H2D-specific indexing behavior

Implement only rules that can be supported by source-code analysis and fixture-based tests.

For each resolved value, record:

```text
filament_slot_id
filament_config_index
extruder_index
plate_id
object_id
volume_id
nozzle_variant
resolution_rule
resolution_evidence
```

Fields may be null when not applicable.

Preserve the distinction between:

- 1-based filament slot identifiers
- Internal zero-based configuration indices
- Extruder identifiers
- Nozzle variants
- Parameter array positions

Do not silently convert one identity into another.

### Partial Resolution

If the required context is missing:

- Preserve the raw parameter array.
- Return `UNRESOLVED`.
- Explain which context is missing.
- Do not select the first element.
- Do not substitute an assumed default.

If multiple plausible mappings exist, return `AMBIGUOUS`.

## 10. Effective-Value Semantics

Separate three concepts:

1. **Stored value** — A value present in the 3MF configuration.
2. **Resolved configuration value** — A value selected through a verified configuration-index and override rule.
3. **Runtime-effective value** — A value demonstrably used during slicing or G-code generation.

P9-B1 may resolve stored and configuration values.

It must not claim runtime-effective values without sufficient evidence.

For each resolved parameter, include a value-level classification such as:

```text
STORED_ONLY
CONFIG_RESOLVED
RUNTIME_VERIFIED
```

Use `RUNTIME_VERIFIED` only when backed by controlled experiments or equivalent authoritative evidence.

Preserve the difference between:

- Explicit values.
- Inherited values.
- Project overrides.
- Printer-derived values.
- Process-derived values.
- Missing values.
- `nil` values.

Do not resolve inherited defaults unless the complete required inheritance chain and precedence rules are available and verified.

## 16. Acceptance Criteria

P9-B1 is complete when:

- A real Bambu Studio 3MF can be parsed without modifying it.
- Relevant project/model/plate metadata can be extracted.
- Raw filament parameters and their provenance are preserved.
- Filament slot identities are represented correctly.
- Parameter arrays are never blindly indexed by filament slot.
- Verified configuration-index rules are implemented.
- Unsupported index mappings produce explicit unresolved results.
- The H2D fixture is handled without false effective-value claims.
- Malformed or malicious archives are rejected safely.
- A standalone diagnostic CLI produces a structured JSON report.
- The existing Worker test suite passes.
- No Worker lifecycle, Feishu schema, or Miaoda UI changes are introduced.
- Documentation clearly separates verified behavior from assumptions.

## 17. Final Status

Use one of:

- `COMPLETE_VERIFIED`
- `COMPLETE_WITH_LIMITATIONS`
- `PARTIALLY_COMPLETE`
- `BLOCKED`

`COMPLETE_VERIFIED` requires sufficient real-fixture evidence for the implemented resolution rules.

If the parser is complete but some effective-value rules lack real experimental evidence, use `COMPLETE_WITH_LIMITATIONS`.

Do not classify unverified effective-value inference as completed functionality.

## 18. Implementation Principles

**Correctness before coverage.**

**Provenance before convenience.**

**Explicit uncertainty before guessed values.**

**Read-only extraction before workflow integration.**

P9-B1 should establish a reliable technical foundation for P9-B2, not attempt to become a complete reimplementation of Bambu Studio's slicing engine.
