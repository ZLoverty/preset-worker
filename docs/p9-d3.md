## D3.6 — Multi-Slot Identity Selection

Use the existing P9-D1 `comparison_core.select_slot()` implementation.

Do not create a new slot-selection algorithm.

### Unique identity

When exactly one project slot matches the native Preset identity:

- Select that slot.
- Preserve its original one-based `slot_id`.
- Record the identity evidence.
- Compare only values associated with that slot.

### Multiple equivalent identities

When multiple project slots have the same exact identity:

1. Collect all matching slot IDs.
2. Inspect all eight target parameter values at those slots.
3. Verify that every parameter required by the existing equivalence policy has reliable slot association.
4. Compare values using the existing normalization rules.
5. Select the lowest matching slot only if equivalence is established.
6. Record `matching_slot_ids` and the `MULTIPLE_EQUIVALENT` reason.

Do not treat duplicate identity as proof of equivalence.

Do not compare parameters before establishing identity.

### Conflicting duplicate identities

If matching slots have different target values:

- Do not select a representative slot.
- Preserve `AMBIGUOUS`.
- Do not emit a misleading MATCH result.

### Incomplete evidence

If slot association or target parameter equivalence cannot be established:

- Preserve `AMBIGUOUS` or the existing unresolved representation.
- Do not silently choose the first slot.

### No identity match

Return `UNRESOLVED`.

Do not fall back to the first slot, parameter equality, `filament_ids`, or `base_id`.

## D3.7 — Slot-Aware Parameter Comparison

Delegate comparison to:

`comparison_core.compare_parameter()`

Use the existing proven slot-indexing rules.

For a four-slot project, a target parameter array with verified filament-slot semantics and four elements may be indexed by the selected slot.

For example:

```text
Project:
  nozzle_temperature = ["230", "220", "225", "230"]

Selected slot:
  1

Preset:
  nozzle_temperature = ["230"]

Compared:
  Project[0] = "230"
  Preset[0]  = "230"
```

The result should be MATCH when numeric normalization confirms equivalence.

Preserve:

- Original project array.
- Original project array index.
- Original Preset value.
- Source paths.
- Selected slot.
- Comparison status.

Do not compare the entire four-element project array against the one-element Preset array after slot selection has been established.

Do not broadcast, truncate, or infer array dimensions.

An array length equal to the number of slots is not, by itself, sufficient evidence of filament-slot semantics.

Use the shared core's established parameter metadata and extraction evidence.
