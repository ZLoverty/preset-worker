## 2. Confirmed defect

P10-D1 reproduced the following behavior using the committed Snapmaker fixture pair:

```text
tests/fixtures/slicers/orca_slicer_snapmaker/pla_test.json
tests/fixtures/slicers/orca_slicer_snapmaker/snapmaker-orca.3mf
```

The selected filament is uniquely resolved:

```text
selection.status = UNIQUE
filament_slot_id = 1
matching_slot_ids = [1]
```

Some comparison rows contain selected scalar values, while `MISSING_IN_PRESET` rows expose the entire original 3MF array.

The audit traced this to:

1. `compare_parameter()` selects the project value.
2. When the Native Preset operand is missing, it returns without comparison elements.
3. `native_consistency._rows()` uses `comparison["project"]["raw_value"]` when elements are absent.
4. The original project array is therefore serialized instead of the selected scalar.

This is a Worker serialization defect, not evidence of ambiguous filament selection.

## 3. Required serialization invariant

For each flattened comparison row, distinguish:

- The original raw source value.
- The slot-selected value.
- The normalized comparison operand.
- The actual comparison status.

`project_value` must represent the selected project operand when a valid selection exists.

It must not switch between selected scalar and raw array solely because the Native Preset operand is missing.

For example, the desired conceptual output is:

```json
{
  "parameter_id": "filament_flow_ratio",
  "project_value": "0.98",
  "project_original_array": ["0.98", "0.98", "0.98", "0.98"],
  "project_source_path": "$.filament_flow_ratio[0]",
  "status": "MISSING_IN_PRESET"
}
```

This is an illustrative target shape. Verify actual field names and selected-slot indexing against source before implementation.

Do not fabricate a scalar when selection is unresolved.

Do not silently choose the first array element.

Do not change `MISSING_IN_PRESET` into `MATCH`.

## 4. Minimal implementation

Inspect whether the existing comparison object already retains the selected project operand.

Prefer using that existing information rather than repeating slot selection in `_rows()`.

If the selected operand is not retained, add the smallest necessary internal field to preserve it.

The serialization path should use one consistent source of truth for the selected operand.

Avoid introducing a second independent selection algorithm.

Preserve existing comparison statuses, diagnostic semantics, target sets, and schema version.

If adding an optional field for original array evidence, use a clear name and do not overwrite existing required fields.

Verify all report consumers before changing the meaning of an existing field.

If changing `project_value` from an array to the selected scalar could affect consumers, document the behavioral change and test the existing report envelope.
