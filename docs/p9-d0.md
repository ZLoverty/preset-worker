# P9-D0 — Cross-Slicer Fixture Collection & Verification

## Background

P9-B implemented non-blocking consistency validation between uploaded BambuStudio Preset JSON and 3MF project files.

P9-C audited the existing implementation and concluded:

- BambuStudio is verified using real project fixtures.
- OrcaSlicer, SnapmakerOrcaSlicer, CrealityPrint, ElegooSlicer, and PrusaSlicer have no verified paired 3MF + Preset fixtures.
- The current BambuStudio validator is not slicer-independent.
- The existing SafeZipReader, comparison semantics, and report structure are candidates for reuse.
- Additional real-world evidence is required before implementing new slicer adapters.

P9-D0 establishes this evidence.

**This phase is strictly fixture collection, inspection, and compatibility verification. No production validator implementation.**

## Objectives

1. Establish a reproducible fixture collection for the five remaining slicers.
2. Inspect actual exported 3MF archive structures.
3. Identify project-side configuration files and filament parameters.
4. Verify correspondence between uploaded Presets and project filament configurations.
5. Determine which existing BambuStudio parsing components can be reused.
6. Produce an evidence-based implementation recommendation for P9-D1 onward.

## D0.1 — Fixture Inventory and Directory Structure

First inspect the repository for existing relevant fixtures.

Do not duplicate files unnecessarily.

Use the existing test fixture conventions if available. Otherwise, propose a minimal directory structure such as:

```text
tests/fixtures/three_mf/
├── bambustudio/
├── orcaslicer/
├── snapmaker_orcaslicer/
├── crealityprint/
├── elegooslicer/
└── prusaslicer/
```

Each slicer directory may contain:

```text
single_filament/
├── project.3mf
├── preset.json       # or preset.ini
└── manifest.json
```

Keep original exported file bytes unchanged.

Do not rename internal 3MF archive members or rewrite Preset contents.

If fixtures are missing, create only the necessary directory structure and collection instructions.

Never fabricate a real fixture.

## D0.2 — Define a Minimal Collection Protocol

Prepare concise instructions for collecting fixtures from each slicer.

The minimum useful fixture is:

- One project containing a simple model.
- One printer.
- One filament slot.
- One custom filament Preset.
- One project saved as 3MF.
- The corresponding filament Preset exported separately.
- Known slicer version and printer model.

Prefer a simple cube or similarly minimal geometry.

The exact model geometry is not important.

The project should be saved after applying the custom filament Preset.

For the first sample, use deliberately recognizable parameter values where the slicer permits them safely, such as:

- Flow ratio: 0.97
- Maximum volumetric speed: 11 mm³/s
- Nozzle temperature: 225 °C
- First-layer nozzle temperature: 230 °C
- Maximum fan speed: 85%

These values are test markers, not printing recommendations. Do not require physical printing or slicing if saving the project is sufficient.

If a slicer restricts these values, use valid alternatives and record them.

Do not modify Preset JSON/INI manually to create the primary real fixture.

The Preset and 3MF must originate from the same slicer session and configuration.

### Additional fixtures

After the minimal single-filament fixture is verified, collect where feasible:

- Two-filament project.
- Deliberate parameter mismatch pair.
- Project with a missing or inherited parameter.
- Alternative 3MF export modes.

Do not block initial investigation because advanced fixtures are unavailable.

## D0.3 — Fixture Manifest

Each fixture must have a manifest.

Suggested structure:

```json
{
  "schema_version": "p9d0.fixture.v1",
  "slicer": "OrcaSlicer",
  "slicer_version": "REPLACE_ME",
  "printer_model": "REPLACE_ME",
  "export_mode": "save_project",
  "project_file": "project.3mf",
  "preset_file": "preset.json",
  "filament_count": 1,
  "expected_filament_name": "REPLACE_ME",
  "expected_slot": null,
  "notes": ""
}
```

Use exact slicer identifiers from the existing Worker registry.

Keep the manifest small.

Do not duplicate all Preset parameters in the manifest.

Do not guess slot IDs.

Use `null` when an identity or slot is unknown.

## D0.4 — Read-Only 3MF Inspector

Implement a small development-only inspection utility.

Suggested command:

```bash
python scripts/inspect_3mf.py \
  --project tests/fixtures/three_mf/orcaslicer/single_filament/project.3mf \
  --preset tests/fixtures/three_mf/orcaslicer/single_filament/preset.json \
  --slicer OrcaSlicer
```

Adapt paths and CLI conventions to the actual repository.

The tool must:

1. Use the existing SafeZipReader where practical.
2. List ZIP archive members.
3. Identify likely configuration files.
4. Detect JSON, INI, and XML configuration formats.
5. Extract candidate filament-related keys.
6. Identify filament preset names, IDs, and slot arrays.
7. Identify the eight P9 target parameters where present.
8. Record the configuration path for each observed value.
9. Report missing and ambiguous evidence explicitly.
10. Produce a concise, deterministic summary.

Do not dump full project configuration or embedded G-code.

Do not extract entire archives to disk.

Do not load large model meshes or toolpaths unless required.

Do not modify the input files.

Enforce ZIP member size, decompression, path traversal, and total extraction limits.

If a member is unsafe or unreadable, report the problem without bypassing the existing security boundary.

Do not automatically infer parameter equivalence from similar names.

## D0.5 — Parameter Evidence Extraction

Investigate the existing eight P9 parameters:

| Canonical parameter | Expected meaning |
|---|---|
| filament_flow_ratio | Filament flow multiplier |
| filament_max_volumetric_speed | Maximum volumetric flow |
| nozzle_temperature | Normal nozzle temperature |
| nozzle_temperature_initial_layer | Initial-layer nozzle temperature |
| fan_min_speed | Minimum cooling fan speed |
| fan_max_speed | Maximum cooling fan speed |
| fan_cooling_layer_time | Cooling threshold |
| slow_down_layer_time | Slowdown threshold |

For each slicer, record:

- Preset key.
- Project configuration key.
- Project archive member.
- Original stored value.
- Value type.
- Unit, when known.
- Array index or slot association.
- Whether the value is explicitly stored.
- Whether the value appears inherited or overridden.
- Evidence supporting any proposed mapping.

Use the classifications defined in P9-C:

- DIRECT
- MAPPED
- CONDITIONAL
- UNRESOLVED
- UNSUPPORTED

A parameter is DIRECT or MAPPED only when real fixture evidence supports both the key mapping and semantics.

If the field exists only in the Preset, mark project-side evidence unresolved.

If the field exists only in the 3MF, mark Preset-side evidence unresolved.

Do not treat missing fields as zero.

## D0.6 — Filament Identity Verification

For every paired fixture, inspect:

- Filament Preset name.
- Filament Preset identifier.
- Project-side filament identity.
- Filament slot index.
- Number of project filament slots.
- Printer compatibility metadata, when available.

Attempt to establish whether the exported Preset corresponds to a unique project filament slot.

Classify identity resolution as:

- UNIQUE
- AMBIGUOUS
- UNRESOLVED

Record the actual identity evidence.

Do not use matching numeric parameter values as proof of filament identity.

Do not assume a single project slot automatically establishes identity.

Explicitly distinguish:

1. Preset and project stored-value comparison.
2. Filament identity correspondence.
3. Runtime-effective configuration equivalence.

D0 does not need to prove runtime-effective equivalence.

## D0.7 — Compatibility Probe

Where sufficient evidence exists, run isolated compatibility probes against the existing BambuStudio 3MF extraction components.

The purpose is to determine whether the archive structure and parameter extraction logic can be reused.

Do not register new slicers in the production Preview dispatcher.

Do not modify the current BambuStudio validator to force compatibility.

Classify each slicer as:

- REUSE_AS_IS
- REUSE_WITH_ADAPTER
- SEPARATE_PARSER_REQUIRED
- INSUFFICIENT_EVIDENCE

A parser successfully reading a file is not sufficient to claim correct validation.

Verify extracted values against the actual project configuration.

When evidence is incomplete, record the limitation.

## D0.8 — Automated Tests

Add tests for the inspection utility and fixture metadata.

At minimum:

1. Valid fixture manifest.
2. Missing project file.
3. Missing Preset file.
4. Invalid ZIP archive.
5. Unsafe ZIP member path.
6. Oversized archive member.
7. JSON configuration detection.
8. INI configuration detection.
9. XML configuration detection.
10. Missing target parameter.
11. Multiple candidate filament slots.
12. Deterministic inspection output.

Use small synthetic test files for utility behavior.

Use actual exported 3MF files for compatibility conclusions.

Do not modify existing P9-B2 test expectations.

## D0.10 — Incremental Workflow

P9-D0 must work even when only some fixtures are available.

Recommended sequence:

1. Audit existing fixtures.
2. Implement the minimal inspector.
3. Generate the initial inventory.
4. Identify missing fixture pairs.
5. Inspect newly supplied fixtures.
6. Update compatibility findings.
7. Recommend the next slicer implementation.

Do not require all five slicers to have fixtures before producing useful results.

If only OrcaSlicer fixtures are available, complete the OrcaSlicer investigation and leave other slicers explicitly pending.

## Constraints

- No production Worker Preview changes.
- No new production validators.
- No Feishu schema changes.
- No Miaoda changes.
- No changes to approval or publication.
- No new slicer routing in Preview.
- No changes to existing BambuStudio comparison semantics.
- No unrelated performance optimization.
- No speculative general-purpose parser framework.
- No unnecessary dependencies.
- No automatic modification of uploaded Presets or 3MF files.

All inspection and compatibility checks must be read-only and reproducible.

## Acceptance Criteria

P9-D0 is complete for a given slicer when:

1. At least one real paired Preset + project 3MF fixture is available.
2. Its slicer version and export mode are documented.
3. Its 3MF configuration structure has been inspected.
4. The eight target parameters have explicit evidence classifications.
5. Filament identity and slot-selection evidence is documented.
6. Parser reuse potential has been assessed.
7. Unresolved limitations are recorded.
8. The next implementation step is clear.

Partial completion across slicers is acceptable.

Do not mark an individual slicer as verified merely because its Preset format is already supported.

4. Verified parameter mappings.
