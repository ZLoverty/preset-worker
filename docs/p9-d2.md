# P9-D2 — CrealityPrint & ElegooSlicer Consistency Adapters

## Background

The Preset Management System supports multiple slicers through the existing `SlicerProcessor` architecture.

P9-B2 implemented BambuStudio-specific consistency validation between uploaded filament Presets and 3MF projects.

P9-D0 established, using real exported fixtures, that both CrealityPrint and ElegooSlicer:

- Store project settings in `Metadata/project_settings.config`.
- Use JSON project configuration with the same eight canonical P9 parameter names.
- Store these parameters as single-element arrays in the available single-filament fixtures.
- Provide exact `filament_settings_id=pla_test` identity correspondence between the project and the supplied Preset.
- Can be read by the existing Bambu-style project extractor.

The available fixtures are:

```text
tests/fixtures/slicers/creality_print/
├── creality.3mf
├── pla_test.json
└── manifest.json

tests/fixtures/slicers/elegoo_slicer/
├── elegoo.3mf
├── pla_test.json
└── manifest.json
```

P9-D1 introduced:

`src/preset_worker/three_mf/comparison_core.py`

This module provides shared stored-value comparison, numeric normalization, explicit filament-slot selection, duplicate-identity equivalence checks, and comparison rows.

The existing BambuStudio validator delegates reusable comparison behavior to this core.

All existing BambuStudio tests pass.

The full test suite has one known unrelated baseline failure in `tests/test_diff_contract.py`:

- Expected: `IMPORTANT_PARAMETER`
- Actual: `OTHER_PARAMETER`

Do not modify this unrelated classification behavior as part of P9-D2.

## Objective

Implement isolated consistency validation for CrealityPrint and ElegooSlicer by reusing the P9-D1 shared comparison core and existing Bambu-style 3MF extraction capabilities.

The implementation must support:

1. Native Preset JSON parsing.
2. Project configuration extraction.
3. Exact filament identity matching.
4. Explicit slot-aware parameter selection.
5. Comparison of the existing eight P9 parameters.
6. Accurate missing/unresolved parameter statuses.
7. Compatible P9 consistency reports.
8. Real fixture-based regression tests.

**Do not enable either slicer in production Preview during this phase.**

Reuse this extraction path where compatible.

- Archive size.
- Member size.
- Malformed metadata.
- Invalid JSON.
- Missing configuration files.

## D2.6 — Filament Identity and Slot Selection

Use the shared P9-D1 slot-selection mechanism.

For the current real fixtures:

```text
CrealityPrint:
  Preset identity: pla_test
  Project identity: pla_test
  Project slot: 1

ElegooSlicer:
  Preset identity: pla_test
  Project identity: pla_test
  Project slot: 1
```

Both should resolve to:

`UNIQUE`

The adapter must:

1. Extract native Preset identity.
2. Extract project filament identities.
3. Perform exact matching.
4. Pass explicit slot evidence to the shared core.
5. Use the selected project slot for parameter comparison.
6. Preserve original project array indices and source paths.

Do not infer identity from matching parameter values.

Do not silently fall back to the first project slot if identity is missing.

Do not use `filament_ids` or `base_id` as a substitute for `filament_settings_id` without verified mapping evidence.

For future multi-slot fixtures, reuse P9-D1 duplicate-identity and slot-equivalence rules.

Do not implement a separate slot-selection algorithm for either slicer.

## D2.7 — Shared Stored-Value Comparison

Delegate all reusable comparison behavior to `comparison_core.py`.

Support the existing comparison statuses:

- MATCH
- MISMATCH
- MISSING_IN_PRESET
- MISSING_IN_3MF
- UNRESOLVED
- AMBIGUOUS
- NOT_COMPARABLE
- NOT_APPLICABLE

Preserve the P9-D1 numeric normalization rules.

Compare only values whose semantic mapping and slot association are established.

Preserve:

- Original Preset value.
- Original project value.
- Selected project slot.
- Original project array index.
- Source paths.
- Parameter identifier.
- Comparison status.

For the current fixtures, project-side one-element arrays should be selected using the proven single filament slot.

Do not compare the entire project array against a scalar Preset value when slot association has been established.

Do not broadcast or truncate arrays.

Do not interpret stored-value equality as runtime-effective equality.
