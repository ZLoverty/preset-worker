# P9-A — Bambu Studio 3MF Project Settings Investigation & Preset Consistency Feasibility

## 1. Objective

Investigate how Bambu Studio stores project settings inside `.3mf` files and determine whether the effective filament parameters used by a sliced project can be reliably compared against a separately submitted Bambu Studio Filament Preset JSON.

This phase is **research, reverse engineering, and feasibility validation only**.

Do not implement production validation, modify the Feishu schema, or change the Miaoda UI.

The goal is to produce a verified technical specification for P9-B (Worker implementation) and P9-C (Miaoda presentation).

## 2. Existing System Context

The current Preset management system consists of:

- Feishu Bitable as the source of truth.
- Submission, PresetVersion, and Preset tables.
- A Python Worker responsible for validation, canonicalization, diff generation, and publishing.
- A Miaoda frontend for submission, preview, and review.
- Slicer-specific processors with a common interface.
- Immutable published PresetVersion records.

The system currently supports multiple slicers, but **P9-A is limited to Bambu Studio**.

The existing BambuStudioProcessor must be inspected and reused conceptually where appropriate.

Important distinction:

- The submitted Filament Preset JSON represents the candidate filament configuration.
- The submitted 3MF represents a project used for testing or printing.
- Project settings may include printer, process, filament, object-level, and project-level overrides.
- A project may contain multiple filament configurations and multiple plates.

The investigation must not assume that a 3MF project contains a single unambiguous effective filament configuration.

## 3. Scope and Non-Goals

### In Scope

1. Inspect the actual internal structure of Bambu Studio 3MF archives.
2. Identify how filament-related settings are stored.
3. Determine how project settings, preset inheritance, and overrides affect effective values.
4. Identify which filament settings can be compared with the submitted JSON.
5. Investigate multi-filament and multi-plate behavior.
6. Establish normalization and comparison rules.
7. Develop experimental fixtures and exploratory scripts.
8. Define a proposed P9-B parser and validator contract.

### Out of Scope

- Production Worker integration.
- Feishu schema modifications.
- Miaoda frontend modifications.
- Workflow status changes.
- Blocking submissions based on 3MF differences.
- Supporting OrcaSlicer, PrusaSlicer, or other slicers.
- Automatically rewriting the submitted Preset JSON.
- Assuming undocumented behavior without experimental verification.

## 5. Investigate 3MF Archive Structure

Collect representative 3MF files generated by Bambu Studio.

Inspect the ZIP archive entries and identify relevant configuration files.

Potential areas to investigate include:

- `Metadata/project_settings.config`
- `Metadata/model_settings.config`
- `Metadata/slice_info.config`
- Other Bambu Studio-specific metadata files

These paths are investigation candidates, not guaranteed requirements.

For each relevant entry, document:

- Actual archive path.
- Data format.
- Example structure.
- Parameter storage conventions.
- Filament preset identification.
- Printer and process configuration.
- Filament-slot mapping.
- Plate-specific configuration.
- Override representation.
- Whether the entry exists before slicing.
- Whether the entry changes after slicing.
- Whether the entry changes after saving or reopening.

Clearly distinguish observations from hypotheses.

Do not assume that a stored parameter is an effective parameter merely because it appears in the archive.

## 6. Determine Effective Filament Settings

This is the highest-priority investigation.

For each candidate parameter, determine:

1. Where it is stored in the submitted Filament Preset JSON.
2. Where it is stored in the 3MF.
3. Whether the 3MF value is explicitly stored or inherited.
4. Whether the 3MF contains the effective value or only a reference/default.
5. Whether project-level overrides can change the effective value.
6. Whether printer or process settings can override the filament value.
7. Whether the parameter is filament-slot-specific.
8. Whether the parameter can vary across plates or objects.
9. Whether the effective value can be reconstructed without opening Bambu Studio.
10. How this behavior was experimentally verified.

Where available, consult Bambu Studio source code to verify serialization, deserialization, configuration merging, and override precedence.

Use source-code evidence and controlled experiments together.

If source code and observed behavior disagree, report the discrepancy rather than choosing one silently.

## 7. Parameter Investigation Matrix

Prioritize the following parameter groups.

### A. Temperature

- Nozzle temperature.
- Initial-layer nozzle temperature.
- Bed temperature.
- Initial-layer bed temperature.
- Bed-temperature fields associated with different build-plate types.

Investigate whether the active build-plate type changes which temperature field is relevant.

### B. Cooling

- Minimum fan speed.
- Maximum fan speed.
- Layer-time cooling thresholds.
- Auxiliary fan settings.
- Overhang and bridge cooling settings where applicable.

Determine whether cooling values belong to filament, process, or printer configuration.

### C. Flow

- Filament flow ratio.
- Maximum volumetric speed.

Investigate numeric representation, units, and effective configuration.

### D. Pressure Advance

- Pressure Advance enablement.
- Pressure Advance coefficient.
- Any relevant project-specific or printer-specific behavior.

Determine whether the parameter is controlled by the filament preset, machine configuration, or other mechanisms.

Do not assume a PA value is active simply because a numeric value is stored.

### E. Retraction

- Retraction distance.
- Retraction speed.
- Deretraction or related settings.

Investigate whether retraction is controlled by the filament preset or inherited from printer/extruder settings.

### F. Context Parameters

- Filament preset name.
- Filament type.
- Printer model.
- Nozzle diameter.
- Process preset name.
- Layer height.
- Plate type.

These may be useful for context validation even when they should not be compared directly with filament JSON.

## 8. Controlled Experiments

Use a known baseline Bambu Studio filament preset and a minimal test project.

For each experiment:

1. Save the baseline Filament Preset JSON.
2. Save the baseline project as 3MF.
3. Change exactly one parameter.
4. Save a new 3MF.
5. Extract and compare the relevant archive entries.
6. Record which files and keys changed.
7. Determine whether the changed value is stored explicitly.
8. Reopen the 3MF in Bambu Studio and inspect the loaded settings.
9. Where practical, slice the project and check whether the change affects the generated configuration or output.

Perform experiments for:

- A filament parameter changed in the preset.
- A filament parameter overridden in the project.
- A parameter inherited from a parent preset.
- A parameter omitted from the JSON.
- A printer-controlled parameter.
- A process-controlled parameter.
- A change of build-plate type.
- Multiple filament slots with different settings.
- Multiple plates.
- Unsliced versus sliced 3MF.
- Save/reopen/resave behavior.

Record the exact Bambu Studio version used.

If the repository does not contain suitable 3MF fixtures and Bambu Studio cannot be run in the available environment, report the limitation and produce a reproducible experiment protocol. Do not fabricate experimental findings.

## 9. Parameter Mapping Specification

Produce a mapping table with at least these columns:

| Field | Description |
|---|---|
| parameter_id | Stable internal identifier |
| display_name | Human-readable parameter name |
| preset_json_path | Exact JSON key/path |
| project_3mf_entry | Actual archive entry |
| project_setting_path | Exact project setting key/path |
| ownership | FILAMENT / PROCESS / PRINTER / PROJECT |
| value_type | Number / Boolean / String / Array / Other |
| unit | Unit or dimensionless |
| cardinality | Global / Per filament / Per plate / Per object |
| inheritance_behavior | Verified inheritance rules |
| override_behavior | Verified override precedence |
| effective_value_available | YES / NO / CONDITIONAL |
| normalization_rule | Required comparison normalization |
| confidence | VERIFIED / PARTIALLY_VERIFIED / UNKNOWN |
| evidence | Fixture, source location, or experiment reference |

Do not populate unknown mappings with guessed paths.

For each parameter, classify it as:

- **DIRECTLY_COMPARABLE** — Both effective values can be reliably obtained and normalized.
- **CONDITIONALLY_COMPARABLE** — Comparison requires verified context such as filament slot, plate type, or resolved inheritance.
- **DISPLAY_ONLY** — Useful information, but not suitable for direct filament-preset consistency checking.
- **UNSUPPORTED** — Effective value cannot be reliably established.

## 10. Multi-Filament and Multi-Plate Investigation

Determine how Bambu Studio represents:

- Filament slot identifiers.
- Filament preset names and identifiers.
- Per-slot filament configurations.
- Mapping between objects and filament slots.
- Mapping between plates and their configurations.
- Unused filament slots.
- Multiple slots with the same filament type.
- Multiple slots using different parameter values.

Investigate how the submitted Filament Preset should be matched to a project filament slot.

Do not automatically compare against the first filament slot.

If multiple possible matches exist, the future validator must report ambiguity rather than silently selecting one.

Determine whether the 3MF alone provides enough information for unambiguous matching.

If not, propose the minimum additional user input required.

## 11. Normalization and Comparison Semantics

Investigate:

- Numeric strings versus numbers.
- Floating-point tolerance.
- Boolean encodings.
- Units and unit conversions.
- Percentage versus ratio representation.
- Array values and array indexing.
- Empty strings, null values, and missing keys.
- Default values.
- Inherited values.
- Project-level overrides.
- Printer-dependent settings.

Distinguish:

- A true value mismatch.
- A parameter missing from one source.
- An inherited value that cannot be resolved.
- An ambiguous filament-slot match.
- A parameter outside the scope of the filament preset.
- A project override that legitimately differs from the submitted preset.

Do not treat missing or unresolved values as mismatches.

Do not apply a single universal numeric tolerance without considering parameter semantics.

## 12. Proposed P9-B Architecture

Based on verified findings, propose a minimal extension compatible with the existing Worker architecture.

Suggested conceptual components:

- `Bambu3MFProjectParser`
- `Bambu3MFSettingsExtractor`
- `FilamentSlotResolver`
- `PresetProjectConsistencyValidator`

These are conceptual names only; adapt to the existing codebase.

The proposed design should separate:

1. Archive parsing.
2. Raw setting extraction.
3. Effective-value resolution.
4. Filament-slot selection.
5. Parameter normalization.
6. Comparison.
7. Structured report generation.

The existing BambuStudioProcessor should remain the authority for parsing and normalizing submitted Bambu Studio preset artifacts where applicable.

Avoid duplicating its rules.

The parser should be read-only and must not rewrite the uploaded 3MF.

## 13. Proposed Validation Report

Design a versioned report schema suitable for both the submission page and reviewer page.

Include:

- Schema version.
- Source slicer and version, if reliably available.
- Preset artifact fingerprint.
- 3MF artifact fingerprint.
- Selected filament slot and selection evidence.
- Project context.
- Per-parameter comparison results.
- Source paths and effective-value provenance.
- Summary counts.
- Warnings and unsupported cases.
- Parser or validation errors.

Proposed comparison results:

- MATCH
- MISMATCH
- MISSING_IN_PRESET
- MISSING_IN_3MF
- UNRESOLVED
- AMBIGUOUS
- NOT_COMPARABLE

The report must distinguish extraction success from consistency success.

Do not define a single PASS/FAIL status that conflates mismatches with missing evidence or parser failures.

Ensure that reports become stale when either source artifact changes.

Do not implement Feishu persistence during P9-A.

## 14. Security and Robustness Investigation

Because 3MF is a ZIP-based format, evaluate:

- Archive size limits.
- Total uncompressed size limits.
- Entry-count limits.
- Compression-ratio limits.
- ZIP bomb protection.
- Path traversal.
- Duplicate archive entry names.
- Malformed JSON/XML.
- Excessive nesting.
- Unsupported compression methods.
- Encoding problems.

Propose safe parser limits appropriate for the Worker.

Do not extract archive members to arbitrary filesystem paths.
