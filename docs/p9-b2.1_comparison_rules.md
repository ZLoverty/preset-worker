# P9-B2.1 Element-Wise Comparison Rules

## Scope

P9-B2.1 compares stored configuration values only. It does not claim that equal stored values are runtime-effective during slicing.

## Rules

- If both supported parameter values are arrays, preserve both complete arrays and compare equal indexes.
- Equal-length arrays produce one element report per index.
- Numeric strings and JSON numbers normalize through Decimal before comparison.
- Different-length arrays are AMBIGUOUS unless a verified correspondence exists. Common indexes are compared and unmatched elements remain in the report with AMBIGUOUS status.
- Scalar versus array is NOT_COMPARABLE. Single-element arrays are not silently broadcast.
- Missing values and invalid numeric values remain explicit.
- Slot or nozzle-variant resolution is not required for stored-array comparison.
- The eight parameter IDs remain unchanged.

Each parameter report contains parameter-level status, comparison_scope, original arrays/raw values, and element-level source paths, values, normalized values, and statuses.

The report also exposes a deterministic flat comparison_rows list. Its path follows the existing preset diff convention: scalar fields use parameter_id and array leaves use parameter_id[index], for example nozzle_temperature[0]. Each row is directly suitable for a future comparison table.

runtime_effective_status is separate and remains NOT_CLAIMED or the independent P9-B1 resolver status. It never changes stored-value MATCH/MISMATCH.
